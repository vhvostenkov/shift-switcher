# Общая касса VHVost

Сервис развёрнут на отдельном РФ-хосте. Публичные продажи и SMTP-очередь выключены;
текущая конфигурация LIVE (`c7c35e51d155`), с выключенными реальными продажами и бесплатной выдачей. Локальные проверки не подтверждают настоящую покупку.

`service.py` обслуживает каталог, защищённую сессию заказа, Init, банковское уведомление,
активацию и освобождение устройства. Цена и продукт определяются сервером. Уведомление
проверяется подписью и независимым GetState. DEMO и LIVE базы разделены.
Возврат блокирует новые активации; уже выданный офлайн-сертификат действует до 30 дней.

LIVE-клиенты Mac и Windows принимают один формат подписанного сертификата Ed25519
и общий лимит двух установок. Платёжный заказ выдаёт ключ только после CONFIRMED.
Отдельная бесплатная owner-лицензия не создаёт заказ и требует явного одобрения владельца.

## Контрольная покупка при закрытых продажах

`commerce.operator prepare-control-checkout` доступен только оператору по SSH.
Он создаёт один заказ с фиксированными email и продуктом, записывает приватную ссылку
в файл 0600 и **не обращается в банк**. Ссылка действует час; токен передаётся фрагментом,
убирается из адреса страницы и отправляется только same-origin POST для защищённой cookie.
Угаданный токен, другой продукт, чужой Origin, устаревшие условия и истёкшая ссылка отвергаются.

Требуются LIVE, подтверждённый магазин, одобренные владельцем свежие либо явно сохранённые прежние реквизиты, опубликованные версии условий,
`legal_terms_approved=true`, `control_checkout_approved=true` и `checkout_enabled=false`.
`receipt_delivery_verified` для подготовки пилота не выставляется: реальный чек и его
доставку ещё предстоит проверить. Обычный `/api/checkout` остаётся закрыт даже при
разрешённом пилоте. Принятие условий покупателем фиксируется до Init; карту и оплату
владелец вводит самостоятельно на странице банка.

```sh
python3 -m commerce.operator --config /private/service-live.json --data /private/live-data \
  prepare-control-checkout --email owner@example.test --output /private/control-checkout.json
```

Это подготовка сценария. Она не означает наличия LIVE-конфигурации на сервере или успешной
оплаты. Для публичного открытия дополнительно нужны проверенные покупка, native activation,
чек НПД «Мой налог», доставка и возврат; затем явное разрешение рабочего checkout.
Ключи, конфигурация, база и контрольная ссылка остаются вне Git.

## Проверки

```sh
python3 -m unittest discover -s commerce -p 'test_*.py'
```

Тесты используют временные ключи, синтетические события и fake bank. Реальные DEMO
и нативные проверки описаны отдельно в [плане выпуска](../docs/COMMERCIAL_RELEASE.md).
Письмо со статусом SENT означает принятие SMTP-сервером; получение проверяется отдельно.

Официальные источники контракта:
- https://developer.tbank.ru/eacq/intro/developer/token
- https://developer.tbank.ru/eacq/intro/developer/notification

## Безопасный ввод DEMO владельцем

В локальном терминале из каталога репозитория:

```sh
python3 -m commerce.configure_demo
```

Оба значения вводятся скрыто, сохраняются вне Git в приватном каталоге
пользователя с правами 0700/0600. Рабочие ключи скрипт не принимает.
Не пересылайте пароли в чат. Сохранение конфигурации само по себе не
отправляет запрос банку и не подтверждает работу эквайринга.

## DEMO API probe

`python3 -m commerce.probe_demo` создаёт один тестовый заказ 499 ₽ без чека
и не выдаёт лицензию. Требует локальной DEMO-конфигурации и отдельного CA bundle
`~/.config/shift-switcher-commerce/tbank-ca.pem`. Его источник:
https://status.tbank-online.com/certificates/ → Russian_Trusted_CA.pem.
Системное хранилище не меняется, проверка TLS и имени хоста обязательна.
Запись платежа хранится только в приватном каталоге 0600. Нельзя запускать
этот probe как публичный checkout: callback URL пока заглушки.

Разрешённый новый хост платёжной формы `pay.tbank-online.com` получен от
аутентифицированного Init API банка 20.10.2026. Остальные произвольные домены
и нестандартные порты отклоняются.
