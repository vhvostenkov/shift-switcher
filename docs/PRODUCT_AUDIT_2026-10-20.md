## Приоритеты продукта

1. **Надёжность до расширения числа функций.** Выполнить текущую нативную приёмку на TextEdit, Notes, Chrome, Telegram и редакторе кода: выделение, слово, отмена, смена фокуса, emoji, Secure Input. Синтетический TextEdit тест старой версии не покрывает новую сборку и физические клавиши.
2. **Источник ввода и уважение пользователя.** Отслеживать `kTISNotifySelectedKeyboardInputSourceChanged`, различать наше и пользовательское переключение, сбрасывать ожидающую автозамену при смене источника. Не менять язык слова, которое пользователь намеренно начал после переключения. Хранить выбранные реальные inputSourceID вместо произвольного первого языка.
3. **Отмена с ясной обратной связью.** Один доступный хоткей отмены и явное «Больше не исправлять это слово»; ничего не отправлять в облако. Не делать автоматическое глобальное обучение по любому backspace.
4. **Раскладка в меню и диагностика.** Показывать текущий RU/EN, причину пропуска (нет AX, Secure Input, приложение исключено, неподдерживаемый источник), а также успешность последней операции. Диагностика без содержимого пользовательского ввода.
5. **Enter/Tab только по отдельной безопасной модели.** Enter может отправить сообщение, Tab уводит фокус; нельзя просто заменить условие keyCode49 на список. Требуется контекст до события, проверка того же AX поля после него и гарантированное отсутствие отложенной записи в новое поле. Если подтверждения нет — пропуск.
6. **Точность.** Создать собственный тестовый корпус RU/EN: имена/бренды, код, URL/email, транслит, аббревиатуры, слова 1–3 буквы, смешанные раскладки. Считать false positive/false negative. Добавлять частотный словарь только с разрешённым источником и явной лицензией; текущие packaged файлы оригинала остаются только объектом исследования.

## Наше приложение: что именно видно в коде

- `Sources/Core.swift`: две фиксированные таблицы RU/EN, покомпонентное преобразование токенов; Double Shift с ограничением длительности и сбросом после сочетаний. Нет динамической карты раскладок.
- `Sources/main.swift:114–148`: Secure Event Input останавливает обработку; смена поколения отменяет отложенную автоматическую операцию; автоматическая коррекция только после пробела, а не посимвольно.
- `Sources/main.swift:150–160`: проверка AXSecureTextField. Не найден отдельный запрет адресной строки браузера. Обычные поля паролей должны отсекаться, но кастомные виджеты нуждаются в живой проверке.
- `Sources/main.swift:161–201`: авто только для буквенного слова длиной >=4, исходник отсутствует в системном словаре, результат присутствует. Есть пользовательские исключения. Это консервативное правило, не доказательство фактической точности.
- `Sources/main.swift:203–216`: PID, AX-элемент, содержимое и выделение сверяются до замены; требуется settable AXSelectedText. Это защищает фокус, но означает отказ там, где редактор не предоставляет AXSelectedText. Нет clipboard/Unicode fallback. Нельзя обещать работоспособность в Electron/Google Docs без отдельного прогона.
- `Sources/main.swift:235–242`: Undo уже есть и требует того же поля и ожидаемого текста. Не считать Undo отсутствующей фичей.
- `Sources/CorrectionPreferences.swift`, `Sources/Settings.swift`: режимы по приложениям и одиночные слова-исключения уже реализованы; SMAppService для автозапуска. Нет импорта/экспорта правил и массового ввода.
- Список исключений переводит Terminal/IDE/менеджеры паролей в manual, а не disabled; поэтому это не равно политике Boomkey. Secure-field защита сохраняется, но для менеджеров паролей разумнее отдельный hard safety deny, проверенный по точным bundle ID.
- `lastEdit` хранит до/после слова и полный `expectedValue` последнего поля в оперативной памяти, до следующего исправления/выхода. Это не сетевой сбор или логирование; при расширении диагностики не выводить эти данные.

## Что можно сделать сейчас без банка и новых разрешений

1. **«Больше не исправлять это слово» после автоматического исправления.** Добавить в меню явную команду, сохраняющую `lastEdit.before` в существующий локальный словарь, без автоматического обучения на любом Undo. У `Edit` сейчас нет флага automatic — добавить его, чтобы не сохранять ошибочное ручное действие как правило. Слова в заголовке меню не показывать: там могут быть чувствительные данные. Не менять текст этой командой; Undo остаётся отдельным действием. Проверки: появляется только после авто; добавляет исходный вариант; состояние переживает перезапуск; ручная коррекция по-прежнему возможна.
2. **Массовый ввод исключений.** Поддержать несколько слов через пробел/запятую/перевод строки с предварительным разбором и итогом «добавлено N, уже есть M, не принято K». Использовать существующую нормализацию и ограничения, не сохранять частично непонятный ввод молча. Это локальная обратимая функция; достаточно unit-проверок разбора/дублей и UI-прогона.

Перед платным запуском важнее обеих функций: Safari/Chrome input+textarea+autocomplete, TextEdit, Telegram, Notes и один Electron-редактор; выделение, целое поле, последнее слово, Undo, быстрая смена фокуса, Secure Event Input и ошибочное срабатывание на командах/URL. Для AX-несовместимых приложений сначала показывать понятный отказ, затем отдельно проектировать fallback.
